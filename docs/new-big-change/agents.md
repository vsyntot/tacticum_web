## Slide 2 — Контекст: AI-агенты — уже не эксперимент

**2026: бизнес-функции хотят AI-ассистентов вчера. IT не успевает.**

- HR-директор хочет бота-онбординг и предчтение резюме — нужен ещё вчера.
- Юр-департамент задыхается от типовых проверок договоров.
- Бухгалтерия отвечает на одни и те же вопросы по командировкам месяцами.
- Клиентский саппорт горит на первой линии — типовые обращения съедают 60–80% времени операторов.
- Каждый отдел хочет «корп-ChatGPT, который знает наши процессы».

**Бенчмарки рынка (2024–2025):**

| Источник | Метрика |
|---|---|
| McKinsey (Generative AI in HR, 2024) | До **70%** задач рекрутинга на первой линии — кандидат на автоматизацию |
| Gartner (CX Predicts 2025) | К 2026 году **30%** взаимодействий контакт-центров будут полностью разрешаться AI-ассистентами без эскалации |
| World Economic Forum (Future of Jobs, 2025) | Routine cognitive work — основная категория, где AI приносит **30–50%** time savings |

**Что мешает:** строить такой стек самим — это 3–4 месяца на инфраструктуру (LLM-шлюз, тенансы, наблюдаемость, безопасность, MCP-инструменты) до первой продуктивной задачи.

## Slide 3 — Что ломается у тех, кто строит сам

| Проблема | Что происходит без платформы |
|---|---|
| 🔴 **Фрагментация LLM-вызовов** | Каждый бот общается со своим провайдером. Нет единого учёта стоимости, нет ротации ключей |
| 🔴 **Нет тенансов** | Бот HR-департамента и бот юр-департамента работают в одной памяти. Утечки контекста |
| 🔴 **Нет каталога инструментов** | Excel-парсер написан 3 раза в трёх ботах. Каждое подключение к 1С — отдельный проект |
| 🔴 **Нет наблюдаемости стоимости** | Месячный счёт от LLM-провайдера = $40 тыс. Кто из ботов сколько потратил — никто не знает |
| 🔴 **Нет управления промптами** | Промпты живут в коде. Поменять формулировку — нужен релиз. Версионирования нет |
| 🔴 **Регрессии без guardrails** | Агент начинает галлюцинировать через неделю после обновления модели. Никто не замечает до жалобы пользователя |
| 🔴 **Каналы коммуникации каждый раз с нуля** | Подключение бота к Telegram, веб-чату, MAX — каждый раз новый интеграционный проект |

**Итог:** первый AI-ассистент строится 4 месяца. Второй — 3 месяца. Третий — 3 месяца. Никакого ROI от платформенного эффекта нет, потому что платформы нет.

## Slide 4 — Решение: готовая мультиагентная платформа

**Архитектурный плюс:** все «жёсткие» вещи (мультитенантность, sovereign-LLM, on-prem, аудит) — берёт на себя платформа. Agents концентрируется на бизнес-домене.

## Slide 5 — Каталог типовых сценариев

Платформа поставляется с предконфигурированными референсными сценариями для типичных бизнес-функций. Это не «жёсткие шаблоны» — это стартовая точка, которая адаптируется под процессы заказчика.

| Сценарий | Описание | Где наибольший эффект |
|---|---|---|
| **HR-онбординг** | Бот сопровождает нового сотрудника по чек-листу, отвечает на FAQ, эскалирует к HR | Снижение нагрузки HR на 40–60% типовых вопросов |
| **Предчтение резюме** | Бот извлекает структуру кандидата, ранжирует по критериям, отдаёт shortlist рекрутеру | Сокращение time-to-shortlist в 3–5 раз |
| **Юр-предчтение договоров** | Бот сравнивает с шаблоном, помечает отклонения, формирует комментарии | Сокращение времени on first review в 2–3 раза |
| **Бух-FAQ** | Бот отвечает на типовые вопросы по командировкам, отпускам, авансовым отчётам, налогам | Снижение нагрузки бухгалтерии на 50–70% по FAQ |
| **Корп-ассистент / knowledge base** | Бот ищет ответы по корп-документам (RAG), помогает с процессами | Сокращение времени на поиск информации в 4–10 раз |
| **Клиентский саппорт первой линии** | Бот разбирает типовые обращения, эскалирует к оператору при необходимости | Automation rate 40–60% по типовому потоку |
| **Тех-саппорт (внутренний IT helpdesk)** | Бот решает типовые IT-запросы, заводит тикеты, эскалирует к админу | Снижение нагрузки IT-саппорта на 40–60% |

Каждый сценарий — это готовый граф агента с типовыми промптами, MCP-инструментами и точками интеграции. Заказчик кастомизирует под свои процессы, не пишет с нуля.

## Slide 6 — Vs. альтернатив

| Подход | Что это | Где ломается |
|---|---|---|
| **«Сами на GPT API + LangChain»** | Свой backend, свой LLM-шлюз, свои тенансы, свои MCP | 3–4 месяца на первый production-бот. Все проблемы из слайда 3 |
| **Готовые ассистенты (типа YandexGPT-бот, готовые Telegram-боты)** | SaaS-боты с UI-конфигурацией | Нет мультиагентности, нет MCP, нет on-prem, нет интеграции с корп-системами |
| **n8n / Make / Zapier + LLM-блоки** | Low-code orchestration | Подходит для простых пайплайнов; на мультиагентных диалогах с состоянием не работает |
| **Корп-копилоты (Microsoft Copilot, Google Duet)** | Глубоко интегрированные с офис-стеком | Привязка к конкретному вендору, нет on-prem, ограничены готовыми сценариями |
| **Tacticum Agents** | Платформа мультиагентных систем с MCP-инструментами | On-prem, sovereign LLM, тенансы, наблюдаемость, готовые сценарии |

**Когда брать Tacticum Agents:** организация хочет 3+ бота для разных бизнес-функций; нужен on-prem или sovereign LLM; есть требование к аудиту и тенансам; интеграция с корп-системами (1С, СПАРК, CRM, BI) — обязательна.

**Когда не брать:** один-единственный простой Telegram-бот без интеграций и без требований к безопасности.

## Slide 7 — Reference-кейсы (фиксируются по факту customer success)

> Размещены индустриальные benchmark-цифры. Конкретные кейсы заказчиков добавляются по мере подписания соглашений о публичности.

### HR-конвейер (типовой эффект)

- Воронка: входящий поток резюме → бот извлекает структуру → ранжирует по критериям → отдаёт shortlist рекрутёру.
- **Эффект по индустриальному benchmark:** time-to-shortlist −60–70%; точность ранжирования сопоставима с senior-рекрутёром при правильно настроенных критериях.
- **Что в стеке:** граф агента + MCP-инструмент парсинга PDF/DOCX + MCP-инструмент LinkedIn/HH-выгрузки + RAG по вашим критериям + интеграция с ATS через REST.

### Юр-проверка договоров (типовой эффект)

- Воронка: входящий договор от контрагента → бот сравнивает с шаблоном → формирует таблицу отклонений → эскалирует юристу.
- **Эффект по индустриальному benchmark:** время первой проверки −50–60%; уровень обнаружения отклонений 90–95% при наличии правильно описанных шаблонов.
- **Что в стеке:** граф агента + MCP-инструмент Word + RAG по корпоративной библиотеке шаблонов + MCP-инструмент чек-листов отклонений.

### Контакт-центр первой линии (типовой эффект)

- Воронка: входящее сообщение клиента → бот распознаёт намерение → отвечает по сценарию или эскалирует оператору.
- **Эффект по индустриальному benchmark:** automation rate 40–60% от типового потока; снижение нагрузки на операторов на 30–50%.
- **Что в стеке:** граф агента + RAG по продуктовой документации + интеграция с CRM через MCP-инструмент + Telegram + веб-чат + SIP-телефония.

## Slide 8 — Безопасность, тенансы, аудит

Платформа спроектирована с учётом требований к корпоративным данным и регуляторных норм РФ.

| Контроль | Реализация |
|---|---|
| **Мультитенантность** | Tenant → Account → Project → User. Изоляция данных по `tenant_id` на уровне query layer |
| **AuthScope** | Каждый вызов LLM, MCP-инструмента и платформенного сервиса содержит контекст безопасности |
| **Identity** | OIDC через Authentik, интеграция с корп-AD/Keycloak/ESIA, API-токены с ограниченным scope |
| **Аудит** | Полный журнал вызовов агентов, LLM, MCP-инструментов и обращений к данным. Экспорт в SIEM |
| **Guardrails** | Политики валидации входа/выхода LLM на уровне арендатора. Маскирование персданных |
| **On-prem** | Развёртывание в контуре заказчика без обращения к зарубежным сервисам |
| **Sovereign LLM** | GigaChat, YandexGPT, Qwen, Kimi, Llama в контуре заказчика |
| **ФЗ-152** | Хранение и обработка персданных в РФ. Согласия фиксируются на уровне арендатора |
| **ФЗ-187 (КИИ)** | Совместимость с доверенными ОС (Astra Linux + РЕД ОС), локальные LLM |
| **Реестр Минцифры** | Подача по классу 04.13 «Системы искусственного интеллекта» |

## Slide 10 — Roll-out: pilot → integration → production

| Этап | Срок | Что внутри |
|---|---|---|
| **Discovery + dataset assessment** | 1–2 недели | Аудит процессов, выбор 1–2 пилотных сценариев, оценка данных для RAG |
| **Pilot** | 4–6 недель | Один граф агента в продакшене на ограниченной аудитории, метрики, итерации |
| **Integration** | 1–2 месяца | Подключение к корп-системам через MCP, разработка кастомных инструментов |
| **Production rollout** | 1–3 месяца | Раскатка на полную аудиторию, обучение операторов / сотрудников, передача наблюдаемости |

**Кого со стороны заказчика нужно подключить:**

| Роль | Зачем |
|---|---|
| Спонсор (CIO / HR-директор / CFO) | Принятие решения и согласование scope |
| Владелец процесса | Постановка задач, валидация сценариев |
| IT-архитектор | Согласование интеграций с корп-системами |
| Безопасность | Согласование контура развёртывания и аудит-политик |

## Slide 11 — С чего начинаем

### Cascade-ask

```
1️⃣  DISCOVERY (60 минут)
    └─ Какие 1-2 сценария дают самый быстрый ROI у вас
       
2️⃣  PILOT (4-6 недель)
    └─ Один граф агента в production
       С реальной аудиторией, с реальными метриками
       
3️⃣  INTEGRATION + ROLL-OUT
    └─ MCP-инструменты под ваши корп-системы
       Production-каналы, наблюдаемость, передача в эксплуатацию
       
4️⃣  PLATFORM CONSOLIDATION (опционально)
    └─ Если у вас уже есть свои AI-ассистенты — миграция на единое ядро
       (см. Tacticum Platform)
```

### Что нужно от заказчика для старта

1. Уточнить бизнес-функцию и желаемый сценарий (HR / юр / бух / саппорт / knowledge).
2. Назначить владельца процесса со стороны заказчика.
3. Подготовить набор корпоративных документов / шаблонов / FAQ для RAG (либо запланировать сбор в фазе discovery).
4. Согласовать контур развёртывания (SaaS / on-prem / гибрид).

Slide 2 · Проблема

Между сценарными ботами и «чистыми LLM»

Сегодня в обслуживании клиентов через цифровые каналы — две крайности, и обе не работают:

ПодходЧто обещаетГде ломается
Классические сценарные ботыКонтролируемые ответы, predictable UXЖёсткое дерево из 200+ узлов. Любое отклонение → «не понимаю вас». Стоимость поддержки растёт линейно
Чистые LLM-боты на APIЕстественный диалог, «можно поговорить о чём угодно»Галлюцинации в проде. Невозможно гарантировать корректный ответ на критичный вопрос. Регуляторика — недоступно
Live-чат с операторамиКачество, но дорогоОператоры тонут в типовых обращениях. SLA рушится на пике

Контакт-центры и службы клиентской поддержки в 2026 году:

  • 60–80% обращений — типовые (статус заказа, политика возвратов, тарифы, FAQ).
  • Стоимость минуты оператора растёт быстрее автоматизации.
  • Регуляторы требуют traceability ответов в финансах, страховании, госуслугах.
  • Импортные платформы (Twilio Flex, Genesys Cloud, Salesforce Service Cloud) больше нельзя использовать — нужны замены.
Slide 3 · Решение

Сценарии + LLM, без иллюзий

Tacticum Forum — гибридный подход: жёсткие сценарные графы для критичных путей + LLM-обогащение для распознавания намерения, обработки уточнений и автоматического выявления новых потребностей.

Архитектурно — это тонкое приложение поверх Tacticum Platform: сценарий описывается как декларативный манифест с расширенным DSL (узлы Start / Message / Input / Condition / Interrupt / Checkpoint / End), а исполняется тем же Agent Runtime, который Tacticum Agents использует для агентов. Slide 6 · A/B-тесты

Управляемая оптимизация без релизов

Главная проблема contact-center automation: «мы поменяли сценарий, и метрика поплыла. Почему?»

Tacticum Forum закрывает этот разрыв встроенными A/B-инструментами на уровне самой платформы.

Что можно проверять

ГипотезаКак тестируем
Новый вариант формулировки повышает FCRСплит 50/50, метрика FCR, статсиг
Изменение порядка чекпоинтов снижает drop-offСплит 30/70, метрика drop-off в каждом чекпоинте
Новый checkpoint перед эскалацией снижает передачи операторуСплит, метрика escalation rate, контроль time-to-resolution
LLM-обогащение узла X повышает пониманиеСплит «классический» vs «LLM-обогащённый», метрика распознавания намерения

Что внутри подсистемы

  • Доменная модель «эксперимент / вариант / правило сплита / метрика / период наблюдения».
  • Детерминированный сплит (по идентификатору диалога) и рандомизированный (с контролем доли).
  • Сбор событий в разрезе варианта: доходимость до чекпоинтов, drop-off, передачи оператору, удовлетворённость.
  • Расчёт статсиг между вариантами с защитой от p-hacking.
  • Контроль состояний эксперимента: создание → запуск → остановка → завершение.
  • Защита от одновременного запуска конфликтующих экспериментов на одном сценарии.
Slide 7 · Отрасли

Кейсы по индустриям

Конкретные кейсы заказчиков фиксируются по мере подписания соглашений о публичности. Ниже — индустриальный benchmark по типовым внедрениям.

Контакт-центры e-commerce

  • Типовой поток: статус заказа, политика возвратов, информация о продукте, изменение доставки.
  • Эффект: automation rate 50–70%, снижение нагрузки операторов на 40%, drop-off −25%.

Финансовые организации (банки, страховые)

  • Типовой поток: баланс/выписка, статус заявки, FAQ по продуктам, навигация по тарифам.
  • Эффект: automation rate 35–50%, FCR +20 п.п., регуляторный аудит ответов через журнал.

Телеком

  • Типовой поток: баланс, тарифы, активация услуг, обращения по качеству связи.
  • Эффект: automation rate 45–60%, снижение AHT операторов на 20–30%.

Государственные и муниципальные сервисы

  • Типовой поток: статус заявления, навигация по услугам, FAQ по документам.
  • Эффект: automation rate 40–55% при правильно описанной карте потребностей.

Внутренний саппорт (HR, IT helpdesk)

  • Типовой поток: статус заявки, FAQ по политикам, навигация по корп-документам.
  • Эффект: automation rate 50–70% за счёт ограниченного словаря и качественной FAQ-базы.

Slide 10 · Старт

От discovery к production

ЭтапСрокЧто внутри
Discovery + dataset assessment1–2 неделиАудит потока, карта потребностей, выбор пилотных сценариев
Pilot4–6 недельОдин сценарий в production на ограниченной аудитории, A/B-тесты, итерации
Integration1–2 месяцаПодключение к CRM/ERP/каналам, развёртывание в контуре
Production rollout2–4 месяцаРаскатка на полный поток, обучение операторов, передача наблюдаемости

Cascade-ask

1️⃣  DISCOVERY (60-90 минут)
    └─ Card-board вашей текущей карты обращений
       Выбор 1-2 топ-сценариев по объёму потока

2️⃣  PILOT (4-6 недель)
    └─ Один сценарий в продакшене
       Реальные метрики, реальная итерация на сценарии

3️⃣  INTEGRATION + ROLL-OUT
    └─ Подключение к CRM/каналам
       Раскатка на полный поток

4️⃣  CONTINUOUS OPTIMIZATION
    └─ A/B-тесты как часть операционного процесса
       Авто-выявление новых потребностей

Что нужно от заказчика для старта

  1. Описать текущий поток обращений (объём, каналы, типовые тематики).
  2. Назначить владельца со стороны контакт-центра / CX-направления.
  3. Подготовить корп-документы / FAQ / шаблоны ответов для RAG.
  4. Согласовать контур развёртывания (SaaS / on-prem / гибрид).

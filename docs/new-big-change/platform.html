Slide 1 · Title

Tacticum Platform

Российская AI-инфраструктура для построения, развёртывания и эксплуатации систем искусственного интеллекта на основе больших языковых моделей.

Slide 2 · Контекст

«Свой собственный AI-стек» сегодня

В каждой крупной организации, строящей продукты с применением LLM, повторяется один и тот же сценарий:

  • разные команды используют разных LLM-провайдеров — нет единого учёта стоимости;
  • каждая команда самостоятельно поднимает MCP-серверы, RAG, память;
  • идентификация пользователей и арендаторов реализована отдельно в каждом продукте;
  • нет единой наблюдаемости вызовов LLM и единого аудита;
  • инфраструктура для on-prem-поставки одного продукта тащит в себе полную копию всей AI-инфраструктуры.

Результат: одни и те же баги фиксятся в трёх местах; пилотный проект на 8 недель превращается в 6 месяцев; экспертиза по безопасности проходится отдельно для каждого продукта.

Slide 3 · Решение

Единое инфраструктурное ядро

Tacticum Platform выносит в общее ядро всё, что повторяется в двух и более AI-приложениях, и предоставляет это как сервисы и SDK. 17 модулей сгруппированы в 6 категорий по типу ответственности.

│                      TACTICUM PLATFORM (ядро)                       │
│                                                                     │
│  RUNTIME   │ Agent Runtime · MCP Runtime · Workflow Spec Engine     │
│  ──────────┼──────────────────────────────────────────────────────  │
│  AI        │ LLM Gateway · Prompt Management · Guardrails           │
│  ──────────┼──────────────────────────────────────────────────────  │
│  DATA      │ Knowledge / RAG · Memory Service · Doc Processing      │

│  ACCESS    │ Identity & RBAC · Tenancy & Quotas · Credential Pool   │
│  ──────────┼──────────────────────────────────────────────────────  │
│  IO        │ Connectors · Event Bus · Embedded MCP Servers          │
│  ──────────┼──────────────────────────────────────────────────────  │
│  OPS       │ Observability & Cost Tracking · Platform SDK           │
└─────────────────────────────────────────────────────────────────────┘
            ▲                       ▲                       ▲
       Agent Manifest         Profile +              Scenario Manifest
       (декларация)         Workflow Manifest        (декларация)
            │                       │                       │
       Tacticum                Tacticum                Tacticum
       Agents                    Dev                    Forum

Принцип: прикладные приложения не реализуют движки — они описывают свои графы, сценарии и workflow как декларативные манифесты. Платформа исполняет.

Один Agent Runtime — три словаря. Agents даёт манифест графа агента, Forum — манифест сценария (с узлами Message / Input / Condition / Checkpoint), Dev — манифест analysis-subagents. Исполняет один универсальный движок.

Slide 9 · Доказательство

На платформе уже работают прикладные продукты

Платформа не «строится в надежде на пользователей». Она — рабочая основа для трёх собственных прикладных продуктов правообладателя:

  • Tacticum Agents — мультиагентные ассистенты для HR/юр/бух/саппорт. Описывает свои графы как Agent Manifest, исполняется на Platform Agent Runtime. Использует LLM Gateway, MCP Runtime, Memory, Connectors.
  • Tacticum Dev — agentic development lifecycle. Использует Identity & RBAC, MCP Runtime (хостит свои Stack-Specific MCP Bundles и Design Token Layer), Knowledge как backbone для RE Knowledge DSL, Workflow Spec Engine для Feature Lifecycle.
  • Tacticum Forum — диалоговые сценарные боты для контакт-центров. Описывает сценарии как Scenario Manifest (расширенный DSL поверх Agent Manifest), исполняется на том же Platform Agent Runtime. Использует LLM Gateway, RAG, Connectors.
Один Agent Runtime обслуживает Agents (мультиагентность), Forum (real-time клиентский диалог), Dev (analysis-subagents). Это и есть «платформенный эффект» — повторное использование, проверенное тремя разными нагрузками.

Каждый продукт — отдельная запись в Реестре отечественного ПО. Платформа — общая основа.

Что это значит для заказчика: инфраструктура валидирована на трёх production-нагрузках с разными профилями. Нет «hello world» в качестве референса.

Модели коммерческой поставки

  • On-prem лицензия — постоянное право использования + ежегодная поддержка.
  • SaaS подписка — для пилотных контуров и небольших арендаторов.
  • ПАК — дистрибутив с предустановленным окружением для субъектов КИИ.

Что нужно от заказчика для старта

  1. Уточнить целевой сценарий (новое AI-приложение / консолидация существующих).
  2. Назначить владельца со стороны заказчика (CIO / руководитель AI-направления).
  3. Подготовить пилотный стенд (виртуальная инфраструктура или dedicated hardware).

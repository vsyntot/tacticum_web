# Chat / Offer Contract

Документ фиксирует production contract для AI chat surfaces и перехода к заявке через `group_id`.

Низкоуровневый REST contract для `/local/rest/tacticum_chat.php` зафиксирован отдельно: `docs/workflow/chat-api-contract.md`.

## Frontend Surfaces

Единый frontend runtime: `local/templates/tacticum/js/chat-runtime.js`, `chat-hero.js`, `chat-calculators.js` and bootstrap `chat-agent.js`.

Покрытые поверхности:

- `/` hero chat: `#main_chat`;
- `/` calculator block: `section#calculator`;
- `/calculator/`: `.ai-chat-container`;
- `/price/`: `.ai-chat-container`.

Inline chat logic на этих страницах не допускается. Новый chat surface должен использовать общий module или отдельный компонент с тем же REST contract.

## Chat Request

Endpoint: `POST /local/rest/tacticum_chat.php`

Required JSON:

```json
{
  "user_message": "Описание задачи",
  "sessid": "bitrix_sessid"
}
```

First message may include:

```json
{
  "startAgent": "ITExpertAgent"
}
```

Follow-up messages include:

```json
{
  "group_id": "uuid-or-upstream-id"
}
```

Rules:

- `user_message` is required and limited by backend validation.
- `sessid` is injected from `BX.bitrix_sessid()` when available.
- `startAgent` is sent only before `group_id` exists.
- `group_id` returned by upstream becomes the current client-side conversation id.

## Chat Response

Expected successful upstream shape:

```json
{
  "response": "AI answer",
  "group_id": "uuid-or-upstream-id",
  "bitrix_url": "https://tacticum.ru/offer/<element-code>/",
  "if_final": true
}
```

`response` is rendered as text, not as trusted HTML. Links such as "Оформить заявку", "Полный расчет" and "Новый расчет" are generated by frontend code only when `bitrix_url` is a non-empty string. Intermediate messages can return `group_id`, but must not show the offer CTA block.

For offer details, `bitrix_url` must be the canonical ЧПУ `/offer/<element-code>/`. New Bitrix offer element `CODE` is generated from `slug.title` plus creation timestamp; `/offer/?ID=<id>` is a legacy entry point and should redirect to the canonical URL.

Controlled error codes handled by frontend:

- `upstream_timeout`;
- `upstream_http_error`;
- `upstream_error`;
- `upstream_contract_error`;
- `curl_error`;
- `validation_error`;
- `invalid_json`;
- `csrf_error` / forbidden response from shared helper.

Frontend copy must stay user-safe and must not expose raw config, stack trace, full payload or PII.

## Offer Prefill

Endpoint: `POST /local/rest/tacticum_prefill.php`

Used only from the hero chat "Оформить заявку" action.

Request:

```json
{
  "group_id": "uuid-or-upstream-id",
  "sessid": "bitrix_sessid"
}
```

GET is not supported. The endpoint returns `405 method_not_allowed` for non-POST requests.

Successful response:

```json
{
  "success": true,
  "group_id": "uuid-or-upstream-id",
  "client_name": "Имя",
  "summary": "Краткое описание заявки"
}
```

Frontend behavior:

- fills `#cta-name` from `client_name`;
- fills `#cta-message` from `summary`;
- sets `window.tacticum_offer_context = { groupId, task }`;
- scrolls to `#contact-form`.

Fallback behavior:

- if prefill fails but the last user message exists, `#cta-message` is filled with that message;
- user remains able to submit the form manually;
- no raw API error is rendered into the form.

## Lead Form Handoff

After prefill, `forms.js` adds `group_id` from `window.tacticum_offer_context.groupId` into the next `data-tacticum-form` payload.

Default form endpoint remains `/local/rest/tacticum_form.php` unless the form has `data-endpoint`.

## Smoke Cases

- First chat message without `group_id` sends `startAgent=ITExpertAgent`.
- Follow-up message sends existing `group_id` and does not resend `startAgent`.
- Upstream timeout shows controlled retry/manual-offer copy.
- Empty/unexpected upstream JSON shows controlled manual-offer copy.
- Intermediate hero chat response with `group_id` and empty `bitrix_url` does not render "Оформить заявку".
- Final hero chat response with non-empty `bitrix_url` renders "Оформить заявку", "Полный расчет" and "Новый расчет" together.
- Final `bitrix_url` opens canonical `/offer/<element-code>/`; legacy `/offer/?ID=<valid>` redirects there.
- Hero "Оформить заявку" with valid `group_id` prefills name/message.
- Hero "Оформить заявку" with invalid/expired `group_id` falls back to manual form filling.
- Form submission after prefill includes `group_id`, `page_url`, `sessid`, `form_id`.

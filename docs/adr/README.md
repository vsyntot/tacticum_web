# Architecture Decision Records — tacticum.ru

Документируем архитектурные решения, которые влияют на всю кодовую базу.
Новые ADR создаёт **Architect-агент** или разработчик при значимом решении.

## Формат файла

`ADR-NNN-короткое-название.md`

| ID | Название | Статус | Дата |
|---|---|---|---|
| [ADR-001](ADR-001-rest-endpoints.md) | REST-эндпоинты как отдельные PHP-файлы | ✅ Принято | 2025 |

| [ADR-005](ADR-005-vendor-analytics-assets.md) | Vendor analytics assets и CSP readiness | ✅ Принято | 2026 |
| [ADR-006](ADR-006-ai-sale-endpoint-paths.md) | AI sale endpoint paths через config | ✅ Принято | 2026 |

## Статусы

| Статус | Значение |
|---|---|
| **Предложено** | Обсуждается, ещё не принято |
| **Принято** | Действует, все обязаны соблюдать |
| **Устарело** | Заменено другим ADR (указать каким) |
| **Отклонено** | Рассматривалось, не принято |

## Как добавить новый ADR

1. Создать файл `docs/adr/ADR-NNN-slug.md` (следующий порядковый номер)
2. Заполнить по шаблону из `.github/agents/architect.md`
3. Обновить таблицу в этом файле
4. Коммит: `docs: add ADR-NNN <название>`
